# 07. Звірка «відправлено ↔ отримано»

Шляхи — відносно `СМП_ОнлайнОбменДанными/cfe/src/`. Уся логіка — у загальному модулі
`CommonModules/СМП_ОнлайнОбменСверка` (далі — «модуль»), рядки — його `Ext/Module.bsl`.

## Призначення

Звіт у базі-джерелі показує, чи кожен документ, що проходить ПРД облікового запису за
період, є в приймачі, в якому він стані і чи збігаються його ключові показники (суми, ПДВ
тощо). Вимоги й рішення — [специфікація](../specs/exchange-reconciliation.md). Ітерація 1 —
лише документи, лише ПКО з пошуком за GUID, звіт без дій над розбіжностями.

```
Джерело                                            Приймач
Отчет.СМП_СверкаДанныхОбмена
 └─ ПолучитьДанныеСверки
     ├─ еталонний набір (період + ПРД)
     ├─ показники за правилами звірки ПКО джерела
     └─ POST gzip /hs/smp_exchange/validate/{Ид} ──▶ СверкаValidatePost
         (порціями по N GUID)                         └─ ОбработатьЗапросСверки
                                                          ├─ стан документів за GUID
     ◀──────────────── JSON 200 ──────────────────────    └─ показники за своїми правилами
 └─ зіставлення, статуси → СКД → табличний документ
```

## Правила звірки

`Справочник.СМП_ПравилаСверки`, власник — `ПравилаКонвертацииОбъектов` (ПКО), без ієрархії
**[код]**. Живуть **в обох базах**; кожна база рахує показник за власним правилом, по HTTP
передаються лише коди показників — код виразів мережею не йде.

| Поле | Зміст |
|---|---|
| `Код` | Рядок 50, унікальний у межах ПКО (`CodeSeries = WithinOwnerSubordination`), без автонумерації. Ключ показника в контракті `/validate` |
| `Наименование` | Рядок 100, заголовок показника у звіті |
| `Вид` | `Перечисление.СМП_ВидыПоказателейСверки`: `Реквизит` / `Выражение` |
| `Реквизит` | `СправочникСсылка.Свойства` — реквізит документа своєї бази |
| `Выражение` | Вираз для `Вычислить`, змінна контексту — `Объект` |
| `Допуск` | Допустима різниця для чисел; 0 — точний збіг. Береться з правила **джерела** |
| `Информативный` | Лише виводиться у звіт, у розбіжність не потрапляє |
| `Порядок` | Порядок показників у звіті |
| `Отключить`, `Комментарий` | Вимкнути, не видаляючи; коментар |

**Вибір реквізиту.** Форма елемента відбирає `Свойства` за власником —
`СМП_ОнлайнОбменСверка.ОбъектСвоейБазы(ПКО)` (рядок 12): для запису `ДляОтправки` — `ПКО.Источник`,
для `ДляПолучения` — `ПКО.Приемник` — і за `Вид = СМП_ВидыСвойств.Реквизит`. Передумова — опис
метаданих обох конфігурацій завантажено (`ЗагрузкаСтруктурыКонфигурации`). Значення
показника — реквізит документа з ім'ям із найменування `Свойства`.

**Перевірки при записі** (`Catalogs/СМП_ПравилаСверки/Ext/ObjectModule.bsl`) **[код]**:

- `Код` і `Наименование` обов'язкові;
- `Вид = Реквизит` — обов'язковий `Реквизит`; посилальний тип у `Свойства.Типы` без
  `Информативный` — відмова (`СвойствоИмеетСсылочныйТип`, рядок 37);
- `Вид = Выражение` — обов'язковий `Выражение`.

Явних прав і команд у формах ПКО / облікового запису в ітерації 1 немає: у ролі
`ПолныеПрава` `setForNewObjects = true`, перехід до правил звірки — панель навігації ПКО.

## Обчислення показника

`ВычислитьПоказатели(Объект, Правила)` (рядок 110) — спільна для обох боків, повертає
`Соответствие` «код → `Структура("Значение")` | `Структура("Ошибка")`» **[код]**:

- `Реквизит` — `Объект[<ім'я реквізиту>]`;
- `Выражение` — `Вычислить` в окремій функції `ВычислитьВыражение` (рядок 244) після
  `УстановитьБезопасныйРежим(Истина)`. Вираз — одне значення, без операторів і циклів;
  процедури (`Записать()`) недоступні. Безпечний режим запис у базу не забороняє — захист
  від помилки автора правила, не від зловмисника. Привілейований режим у безпечному режимі
  **ігнорується**. Що не вміщується у вираз — експортна функція загального модуля, яку
  вираз викликає;
- неінформативний показник, що повернув посилання, — `Ошибка`;
- помилка одного показника не зупиняє решту;
- документ читається `Ссылка.ПолучитьОбъект()` (`ВычислитьПоказателиДокумента`, рядок 151);
  не прочитався — `Ошибка` на кожному показнику.

**Нормалізація** (`НормализоватьЗначение`, рядок 215): число й булево — як є; рядок —
`СокрЛП`; дата — `XMLСтрока`; `Неопределено`/`Null` — `Неопределено` (JSON `null`); решта,
зокрема посилання, — `Строка(Значение)`.

**Порівняння** — лише в джерелі (`ЗначенияСовпадают`, рядок 191): різні типи — розбіжність
(порожнє не дорівнює нулю); число — `|джерело − приймач| ≤ Допуск`; рядок, дата, булево —
точно; `Информативный` не порівнюється.

## Контракт `/validate`

`POST /hs/smp_exchange/validate/{ИдентификаторОбмена}`, шаблон `Сверка` HTTP-сервісу
`СМП_ОбменДанными`, обробник `СверкаValidatePost` — див.
[03 · HTTP-сервіс приймача](03-cherhy-i-transport.md#http-сервіс-приймача--httpservicesсмп_обменданными).
Повний опис — [специфікація, розділ 3б](../specs/exchange-reconciliation.md#3б-контракт-validateидентификаторобмена).

- Запит — JSON у gzip: `Версия` (= `ВерсияКонтракта()` = 1), `ИмяПравила` (код ПКО),
  `Показатели` (коди), `Объекты` (GUID). Один ПКО на запит.
- Відповідь `200` — JSON без стиснення, `application/json; charset=utf-8`: на кожен GUID
  `Найден`, `Тип`, `Номер`, `Дата`, `Проведен`, `ПометкаУдаления`, `Показатели`
  (`Значение` / `Ошибка` / `НеНастроен`); некоректний GUID — `Ошибка` на цьому об'єкті.
- Помилки рівня запиту — JSON `{Версия, Ошибка}`: `404` — немає облікового запису
  `ДляПолучения`; `400` — тіло не gzip/JSON, не та структура, невідома версія (з
  `ПоддерживаемыеВерсии`); `422` — немає ПКО з таким кодом або ПКО конвертує не документ;
  `500` — непередбачена помилка, запис у журнал реєстрації (`ИмяСобытияЖурнала()`).

Приймач (`ОбработатьЗапросСверки`, рядок 305): ПКО за кодом серед ПКО облікового запису, тип
документа — з `ПКО.ТипПриемника`; правила звірки ПКО з кодами із запиту; стан — одним
запитом за `Ссылка В (&Ссылки)`; показники — лише для знайдених **[код]**.

## Джерело: збір і статуси

`ПолучитьДанныеСверки(Параметры)` (рядок 515) **[код]**:

1. Перевірка параметрів: запис `ДляОтправки`, заповнені адреса підключення й
   `ИдентификаторОбмена`, тип — документ, коректний період. Помилки налаштування —
   виняток з текстом для користувача, до будь-якого HTTP-запиту.
2. ПКО запису з `ТипИсточника = "ДокументСсылка.<Тип>"`, не помічений на видалення; немає
   або кілька — виняток «не поддерживается».
3. Еталонний набір: документи типу за період з `Дата ≥ ДатаНачалаВыгрузкиДокументов`, що
   проходять СКД-відбір ПРД (`СМП_ОнлайнОбменСобытия.ПроверитьОбъектПоУсловиямОтбора`, по
   одному документу); помічені на видалення включаються. Порожній набір — порожній
   результат без HTTP-запитів.
4. Запити порціями по `РазмерПорции` GUID (типово 50), тайм-аут — `Таймаут` (типово 60 с);
   адреса й Basic-авторизація — `СМП_ОнлайнОбмен.ПолучитьНастройкиТранспортаОбменаДанными`.
   Помилка транспорту або відповідь не `200` — «помилка запиту» на всіх документах порції,
   решта порцій обробляється. Відповідь не-JSON (старий приймач без `/validate`, платформний
   404 з HTML) — текст «…обновите расширение в приемнике».
5. Результат — `ТаблицаЗначений`: рядок «документ × показник», документ без показників —
   один рядок.

Статус документа — перший, що підходить (`СтатусыСверки`, рядок 487):

| Статус | Коли |
|---|---|
| Ошибка запроса | порція не отримала коректної відповіді |
| Не найден | документа немає в приймачі (або некоректний GUID) |
| Состояние отличается | різні `Проведен` або `ПометкаУдаления` |
| Расхождение показателей | хоч один неінформативний показник поза допуском |
| Показатель не проверен | `Ошибка` чи `НеНастроен` хоч на одному показнику |
| Совпадает | решта |

## Звіт

`Reports/СМП_СверкаДанныхОбмена`, у підсистемі `СМП_ОнлайнОбменДанными` **[код]**:

- параметри — реквізити звіту: `УчетнаяЗапись` (лише `ДляОтправки`), `ТипДокумента` (список
  вибору з `ОбъектыКВыгрузке` запису), `НачалоПериода`/`КонецПериода` (типово минулий
  місяць), `РазмерПорции`, `Таймаут`, прапорець `ТолькоРасхождения` (ховає «Совпадает»);
- власна форма `ФормаОтчета` запам'ятовує обмін, тип документа, порцію, тайм-аут і
  «Только расхождения» між відкриттями (`AutoSaveDataInSettings`), період — ні;
- `ПриКомпоновкеРезультата` (модуль об'єкта звіту) — параметри → `ПолучитьДанныеСверки` →
  зовнішній набір `ДанныеСверки` основної СКД → табличний документ;
- СКД: групування «документ (зі станом у джерелі й приймачі) → рядки показників»;
  розбіжність і статус ≠ «Совпадает» — червоним; розшифровка відкриває документ джерела.
  Остаточну форму виведення автор підбирає в схемі КД.

Формування синхронне; фонове завдання — наступна ітерація.

## Обмеження ітерації 1

- Лише документи; ПКО з пошуком за полями (номер + дата), «1 → 2», два ПКО на один тип —
  не підтримуються.
- Документ, що після відправки перестав проходити ПРД, і зворотна звірка («є в приймачі,
  немає в джерелі») — не контролюються.
- Повнота заповнення реквізитів, дії над розбіжностями, явні права й команди — наступні
  ітерації ([специфікація, розділ 8](../specs/exchange-reconciliation.md#8-поза-межами)).
- Розходження правил звірки між базами свідомо допускається; синхронізації немає.
- **Застереження: за наявності правил звірки перезавантажуйте правила КД2 режимом
  оновлення.** Режим заміни (`ЗагрузкаКонвертацииXML`) видаляє ПКО безпосередньо — разом з
  ними зникають і підпорядковані правила звірки.
