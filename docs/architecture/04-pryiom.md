# 04. Прийом: від HTTP-запиту до записаного об'єкта

## Ланцюжок

1. `HTTPServices/СМП_ОбменДанными` → `ОбменДаннымиDataPost`: обліковий запис `ДляПолучения` за
   `ИдентификаторОбмена`, gzip → рядок, `ДобавитьСообщениеВОчередьВходящих`, відповідь 201
   ([03](03-cherhy-i-transport.md#http-сервіс-приймача--httpservicesсмп_обменданными)).
2. Фонове завдання `СМП_ОнлайнОбмен.ОбработатьВходящиеСообщения`: цикл по `Новое` за `ТаймШтамп`,
   `ВОбработке`, виклик `СМП_ОнлайнОбменСобытия.ОбработатьВходящееСообщение`.
3. `ОбработатьВходящееСообщение` створює `Обработки.СМП_ОнлайнОбменКонвертацияОбъектов`,
   задає `мУчетнаяЗаписьОбмена`, `мСтрокаJSON` і викликає `ВыполнитьЗагрузку()`.
4. Якщо `мОшибки` не порожній — повертається текст помилок → `ОшибкаОбработки`; інакше
   повідомлення видаляється (або `Обработано` у налагодженні).

## `ВыполнитьЗагрузку` (обробка конвертації)

```
ВыполнитьДействияПередЧтениемДанных
  ├─ параметри з облікового запису: ЗагружатьДанныеВРежимеОбмена,
  │  ЗаписыватьВИнформационнуюБазуТолькоИзмененныеОбъекты, Наименование
  ├─ Преобразовать_JSON_В_Соответствие   (ПрочитатьJSON → Соответствие)
  ├─ ЗагрузитьПравилаОбмена               (ПКО/ПКС/ПКЗ/алгоритми облікового запису-приймача)
  └─ обробник конвертації ПередЗагрузкойДанных
ПроизвестиЧтениеДанных
  ├─ обробник ПослеЗагрузкиПараметров
  ├─ ЗагрузитьИнформациюОТипахДанных
  └─ ПрочитатьОбъект(...) для кожного об'єкта (корінь — масив або один об'єкт)
ПровестиЗаписьНеЗаписанныхОбъектов        (відкладений запис створених «за посиланням»)
ВыполнитьДействияПослеЗавершенияЧтенияДанных  (обробник ПослеЗагрузкиДанных)
```

Транзакцій немає (код `НачатьТранзакцию` закоментовано) — частково завантажене повідомлення
не відкочується **[код]**.

## `ПрочитатьОбъект` — один об'єкт

1. ПКО шукається **за ім'ям** з поля `ИмяПравила` пакета (`ТаблицаПравилКонвертации.Найти`).
   Немає правила з таким кодом у приймачі → об'єкт **мовчки пропускається** **[код]**.
   Тип об'єкта береться з `ТипПриемника` ПКО приймача.
2. Обробник ПКО `ПередЗагрузкой` і глобальний `ПередЗагрузкойОбъекта`.
3. Пошук за блоком `Ссылка` — `НайтиОбъектПоСсылке`:
   - якщо ПКО має `СинхронизироватьПоИдентификатору` — спершу за `{УникальныйИдентификатор}`
     (`Менеджер.ПолучитьСсылку(UUID)`);
   - далі за полями пошуку ПКС (якщо не знайшли за UUID і дозволено
     `ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`), з підтримкою алгоритму
     `ПоследовательностьПолейПоиска`;
   - не знайдено → створення нового (з тим самим UUID, якщо синхронізація за ідентифікатором),
     крім `НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска`;
   - знайдено і `НеЗамещать` без обробника `ПриЗагрузке` → об'єкт не змінюється.
4. Обробник `ПриЗагрузке`, заповнення властивостей і табличних частин (`ПрочитатьСвойство_*`,
   `ЗагрузитьТабличнуюЧасть`) — посилальні значення так само шукаються/створюються.
5. Перевірка дати заборони змін (`ЗапретИзмененияДанныхПоДате`, БСП).
6. Запис:

| Тип | Як пишеться |
|---|---|
| Документ | Режим з пакета/стану: відміна проведення, якщо в приймачі проведений, а в пакеті ні; проведення, якщо в пакеті `Проведен`; інакше запис. Пометка удаления знімається при проведенні. `ДополнительныеСвойства.СМП_ОтключитьРегистрациюВОчереди = Истина` (без луни), `ВерсионированиеОбъектовКомментарийКВерсии = "SimplyExchange: <ім'я>"`. `ОбменДанными.Загрузка = ЗагружатьДанныеВРежимеОбмена`. |
| Документ, помилка проведення | `ЗаписатьДокументВБезопасномРежиме`: `Проведен = Ложь`, запис у режимі `Загрузка`; помилка (код 25) — у `мОшибки` |
| Довідник, ПВХ тощо | `ЗаписатьОбъектВИБ`: завжди `ОбменДанными.Загрузка = Истина`; помилка → виняток |
| Регістр відомостей | Набором або записом, з перевірками `НеЗамещать` і зміненості |

7. Обробник `ПослеЗагрузки` ПКО і глобальний `ПослеЗагрузкиОбъекта`.

## Режим `ЗагружатьДанныеВРежимеОбмена`

- `Истина` — документи пишуться з `ОбменДанными.Загрузка = Истина`: без перевірок і бізнес-логіки
  `ПередЗаписью/ПриЗаписи`, але проведення **[гіпотеза]** при цьому все одно виконується
  платформою (обробка проведення не блокується прапорцем `Загрузка`).
- `Ложь` — повноцінний запис/проведення з усіма обробниками конфігурації-приймача.

## Обробка помилок

- Помилки, що потрапляють у `мОшибки`: невдалий JSON (через `ФлагОшибки`), обробники
  конвертації, виняток у `ПроизвестиЧтениеДанных` (у т.ч. невдалий запис довідника),
  помилка проведення документа.
- Протокол (`ЗаписатьВПротоколВыполнения`) у фоновому завданні йде в `Сообщить` — повідомлення
  фонового завдання, файл протоколу не ведеться (`ИмяФайлаПротоколаОбмена` порожній) **[код]**.
