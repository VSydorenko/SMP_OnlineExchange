      `v8storagekit:sync`, оновити базу агента (`operation=build`), лише потім код.

## Кроки

Порядок — за залежностями: перелічення → довідник → роль/навігація → модуль → сервіс → звіт.

### 1. Версія розширення
- [ ] `Configuration.xml`: `Version` 3.2.0.4 → 3.3.0.1.

### 2. Перелічення `СМП_ВидыПоказателейСверки`
- [ ] `Enums/СМП_ВидыПоказателейСверки`: значення `Реквизит`, `Выражение` (синоніми).

### 3. Довідник `СМП_ПравилаСверки`
- [ ] Метадані: власник `Catalog.ПравилаКонвертацииОбъектов`; код — рядок 50,
      `CodeSeries = WithinOwnerSubordination`, `CheckUnique`, без автонумерації; найменування
      100; без ієрархії. Реквізити: `Вид`, `Реквизит` (`CatalogRef.Свойства`), `Выражение`
      (рядок необмежений), `Допуск` (15.2), `Информативный`, `Порядок`, `Отключить`,
      `Комментарий`.
- [ ] Модуль об'єкта: `ОбработкаПроверкиЗаполнения` — `Реквизит` обов'язковий для виду
      `Реквизит`, `Выражение` — для виду `Выражение`; посилальний тип у `Свойства.Типы` без
      `Информативный` — відмова з повідомленням.
- [ ] Форма елемента: поля; видимість `Реквизит` / `Выражение` за `Вид`; вираз —
      багаторядкове поле; параметри вибору `Реквизит`: `Владелец` = `ПКО.Источник`
      (обліковий запис `ДляОтправки`) або `ПКО.Приемник` (`ДляПолучения`),
      `Вид = СМП_ВидыСвойств.Реквизит`.
- [ ] Форма списку — автоматична (окремої не робимо).

### 4. Права й навігація — наступна ітерація
Явних прав і команд не додаємо **[рішення]**. У ролі `ПолныеПрава` `setForNewObjects = true` —
нові об'єкти отримують повні права за замовчуванням. Перехід з форми ПКО до підпорядкованого
довідника платформа зазвичай додає сама — перевірити на кроці 9.

### 5. Загальний модуль `СМП_ОнлайнОбменСверка`
Серверний, без виклику сервера, як `СМП_ОнлайнОбмен`.
- [ ] `ВычислитьПоказатели(Объект, Правила)` — реквізит / `Вычислить` у безпечному режимі
      (окрема функція), помилка на показнику, нормалізація значень (етап 3 специфікації).
- [ ] Порівняння значень: число з допуском, рядок після `СокрЛП`, дата й булево точно,
      різні типи — розбіжність, `Информативный` пропускається.
- [ ] `ОбработатьЗапросСверки(УчетнаяЗапись, ТелоЗапроса)` — приймач: версія, ПКО, правила,
      стан одним запитом, показники; повертає код стану й тіло (етап 4).
- [ ] `ПолучитьДанныеСверки(Параметры)` — джерело: ПКО типу (кілька — помилка), еталонний
      набір з ПРД, стан і показники джерела, запити порціями, зіставлення, статуси; повертає
      таблицю значень для СКД (етапи 5–6).
- [ ] Перевірка без HTTP: `unica.runtime.execute` у базі агента — `ВычислитьПоказатели` і
      `ОбработатьЗапросСверки` на документі УНФ.

### 6. HTTP-сервіс
- [ ] `HTTPServices/СМП_ОбменДанными`: шаблон `Сверка` — `/validate/{ИдентификаторОбмена}`,
      метод `POST`, обробник `СверкаValidatePost`.
- [ ] Обробник: обліковий запис `ПолучитьУчетнуюЗаписьОбменаПоИд(Ид, Истина)`, далі —
      `СМП_ОнлайнОбменСверка.ОбработатьЗапросСверки`; JSON-тіла помилок; `500` + журнал
      реєстрації.

### 7. Звіт `СМП_СверкаДанныхОбмена`
- [ ] Метадані звіту; основна СКД: зовнішній набір із полями етапу 6 специфікації;
      параметри `УчетнаяЗапись`, `ТипДокумента`, `Период`, `РазмерПорции` (50),
      `Таймаут` (60).
- [ ] Варіанти «Розбіжності» (типовий, `Статус ≠ «Збігається»`) і «Усі документи»:
      рядки — документи зі станом, колонки — показники; `Расхождение` — червоним.
- [ ] Модуль об'єкта: `ПриКомпоновкеРезультата` — параметри →
      `СМП_ОнлайнОбменСверка.ПолучитьДанныеСверки` → зовнішній набір → виведення.
- [ ] Власна форма звіту (Р1): список вибору `ТипДокумента` з `ОбъектыКВыгрузке` обраного
      запису; відбір `УчетнаяЗапись` за `ДляОтправки`.
- [ ] Звіт — у підсистему `СМП_ОнлайнОбменДанными` (Р2).
