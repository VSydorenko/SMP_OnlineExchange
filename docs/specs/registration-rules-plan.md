# Правила реєстрації: скомпільований запит замість компоновки — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** при записі документа реєстрація виконує збережений скомпільований запит замість
компоновки СКД; зламане правило дає рядок черги `ОшибкаРегистрации`, а не мовчазне
розширення відбору чи падіння запису.

**Architecture:** новий загальний модуль `СМП_ОнлайнОбменПравилаРегистрации` тримає весь
контур: побудова схеми (текст набору `ВЫБРАТЬ *`), компіляція при записі облікового запису,
читання правил (кеш ПовтИсп з ключем «тип документа × версія правил»), застосування до масиву
посилань. Споживачі — підписка запису документа, звірка, команди черги й списку облікових
записів — лише викликають модуль.

**Tech Stack:** 1С:Підприємство 8.3.27, режим сумісності розширення 8.3.17; Designer platform
XML; Unica MCP (метадані, форми, збірка, синтаксис); БСП (`ОбщегоНазначения`,
`ОбщегоНазначенияКлиентСервер`); перевірки — pwsh-скрипти через зовнішнє з'єднання (COM) до бази
агента.

**Spec:** [`docs/specs/registration-rules.md`](registration-rules.md) — читати разом із планом.

## Правила виконання

План виконує окрема сесія-виконавець скілом `superpowers:executing-plans`. Архітектор і той, хто
приймає рішення по ходу, — сесія, з якої запущено виконання (її ім'я виконавець отримує в
стартовому повідомленні). Людина тестує після реалізації (КТ у Task 7).

1. **Одна сесія за раз.** Робоча копія й база агента `unf_test_claude` спільні: поки працює
   виконавець, архітектор не змінює файли й не збирає базу.
2. **Не імпровізувати — доповідати архітектору.** Будь-яке розходження з «Expected» (помилка
   валідації, синтаксису, збірки чи перевірки; Unica відмовляє або робить не те; код плану не
   компілюється) — **зупинитися**, нічого не обходити. Надіслати архітектору (SendMessage):
   завдання і крок, точна команда, повний вивід, що змінено й не закомічено. Виконати рішення
   дослівно; у коміті — рядок `Відступ від плану: <коротко>, рішення архітектора`.
3. **План і специфікацію не змінювати**, крім галок `[x]` — їх виконавець ставить сам.
4. **Зупинки на рецензію** після Task 2, Task 4 і Task 6: «Task N готово, коміти <хеші>»,
   далі — лише після «далі».
5. **Межі репозиторію** (`CLAUDE.md`): сховище — тільки читання; пише лише в базу агента;
   `-Apply`, `git push`, PR — лише на прохання людини; підрядки `лиценз`, `ліценз`, `license`,
   `HASP` у виводі платформи — стоп і доповідь.
6. **Не відправляти дані в живі бази.** У базі агента є облікові записи на відправку до
   реальних приймачів; вони вивантажують `ЗаказПокупателя`, `ПередачаТоваровМеждуОрганизациями`,
   `ДополнительныеРасходы`, `ПриходнаяНакладная`, `РасходыПриИмпорте`. Документи цих типів
   **не записувати**. Усі перевірки — на `Документ.РасходнаяНакладная` і тестових облікових
   записах з назвою `ТЕСТ агента: …` та адресою `http://127.0.0.1:9/`.
7. **Не клікати клієнт 1С.** Робочий стіл машини — RDP-сесія людини. Форми перевіряє людина (КТ).
8. **Коміти** — лише свої зміни поточного завдання, повідомлення з плану.

## Global Constraints

- Платформа 8.3.27.x; режим сумісності розширення `Version8_3_17` (не підвищувати).
- Розширення працює й на БСП 3.0 (BAS Бухгалтерія): повідомлення користувачу — лише
  `ОбщегоНазначенияКлиентСервер.СообщитьПользователю`.
- Формат — Designer platform XML під `СМП_ОнлайнОбменДанными/cfe/src`. BSL-файли — UTF-8 з BOM,
  CRLF; правки через `sed` у Git Bash — лише `sed -b`.
- Префікс `СМП_`. Імена: модуль `СМП_ОнлайнОбменПравилаРегистрации`; константа й ФО
  `СМП_ВерсияПравилРегистрации`; значення переліку `ОшибкаРегистрации`; реквізити ТЧ
  `ОбъектыКВыгрузке` — `ТекстЗапроса`, `ПараметрыЗапроса`.
- Код, синоніми, повідомлення 1С — російською; тексти користувачу — `НСтр("ru = '...'")`.
- Документ ідентифікується повним ім'ям (`Документ.РасходнаяНакладная`) — параметр
  `ПолноеИмяДокумента` скрізь.
- Текст набору СКД — рівно:
  `ВЫБРАТЬ РАЗРЕШЕННЫЕ * ИЗ <ПолноеИмяДокумента> КАК ОБ ГДЕ ОБ.Ссылка В (&ПараметрСсылка)`
  (з переносами рядків, як у специфікації 5.1).
- Перевірка правил і кеш — у привілейованому режимі.
- Версія розширення: `3.3.0.2` → `3.4.0.1`.

## Уточнення специфікації (рішення архітектора при плануванні)

- **Обліковий запис з `ПометкаУдаления` або `НастройкаОбмена = ДляПолучения` не
  компілюється** при записі (рядки лишаються як є). Інакше зламаний відбір не дав би помітити
  запис на видалення. Такі записи в кеш однаково не потрапляють.
- **Міграція схем у формі** — в `ПолучитьСКДИзТабЧасти` модуля об'єкта (одне місце: усі схеми
  потрапляють у форму звідти), а не в `ИнициализироватьКомпоновщик` (специфікація 6.4).
- `УстановитьСтатусНовое` модуля черги ставить `Обработано` (помилка, викликів немає) —
  виправляється й використовується повторною перевіркою.
- `ЭталонныйНабор` звірки не експортний — перевіряється синтаксисом і КТ людини, не COM.

## Review Focus

1. **Обліковий запис зі зламаним відбором помічають на видалення** — запис проходить
   (Task 2, перевірка `t2: deleted with dead field saves`).
2. **Документ раніший за дату початку при зламаному правилі** — жодного рядка
   `ОшибкаРегистрации` (Task 4, `t4: date before start -> no row`).
3. **«Обработать сообщение» на рядку `ОшибкаРегистрации`** — нічого не обробляється, рядок
   лишається (Task 4, `t4: guard keeps error row`).
4. **Повторна перевірка з дублікатами** одного документа — рівно один рядок іде далі (Task 6,
   `t6: duplicates collapsed`).
5. **Правило без жодної умови відбору** (порожній відбір або схеми немає) — проходять усі
   документи типу (Task 1, `t1: no filter passes all`, `t1: undefined schema passes all`).

```powershell
$ErrorActionPreference = 'Stop'
$BF = [Reflection.BindingFlags]
function G($o, [string]$n) { ,([System.__ComObject].InvokeMember($n, $BF::GetProperty, $null, $o, $null)) }
function SetP($o, [string]$n, $v) { [void][System.__ComObject].InvokeMember($n, $BF::SetProperty, $null, $o, @(,$v)) }
function C($o, [string]$n) { $a = [object[]]@($args); ,([System.__ComObject].InvokeMember($n, $BF::InvokeMethod, $null, $o, $a)) }
function Err($e) { $x = $e.Exception; while ($x.InnerException) { $x = $x.InnerException }; $x.Message }
# Рядок з'єднання — з гітігнорованого v8project.local.yaml (Srvr=…;Ref=…; + user), значення в лапках.
$local = Get-Content (Join-Path $PSScriptRoot '..\..\СМП_ОнлайнОбменДанными\v8project.local.yaml') -Raw
$conn = ([regex]::Match($local, "connection:\s*'([^']+)'").Groups[1].Value -split ';' | Where-Object { $_ } |
  ForEach-Object { $k, $v = $_ -split '=', 2; "$k=""$v""" }) -join ';'
$usr = [regex]::Match($local, "user:\s*'([^']+)'").Groups[1].Value
$v8 = (New-Object -ComObject V83.COMConnector).Connect("$conn;Usr=""$usr"";")
function NewO([string]$t) { if ($args.Count) { ,(C $v8 'NewObject' $t @args) } else { ,(C $v8 'NewObject' $t) } }
function Typ([string]$t) { ,(C (C (NewO 'ОписаниеТипов' $t) 'Типы') 'Получить' 0) }
function Str($x) { C $v8 'String' $x }
function Cnt($coll) { [int](C $coll 'Количество') }
function At($coll, [int]$i) { ,(C $coll 'Получить' $i) }
function Enum([string]$e, [string]$v) { ,(G (G $v8 $e) $v) }
function Mod([string]$n) { ,(G $v8 $n) }
function Arr($items) { $a = NewO 'Массив'; foreach ($i in $items) { [void](C $a 'Добавить' $i) }; ,$a }
function Q([string]$text, $params) {
  $q = NewO 'Запрос'; SetP $q 'Текст' $text
  if ($params) { foreach ($k in $params.Keys) { [void](C $q 'УстановитьПараметр' $k $params[$k]) } }
  ,(C (C $q 'Выполнить') 'Выгрузить') }
function AddF($coll, [string]$field, [string]$kind, $val) {
  $e = C $coll 'Добавить' (Typ 'ЭлементОтбораКомпоновкиДанных')
  SetP $e 'ЛевоеЗначение' (NewO 'ПолеКомпоновкиДанных' $field)
  SetP $e 'ВидСравнения' (Enum 'ВидСравненияКомпоновкиДанных' $kind)
  SetP $e 'ПравоеЗначение' $val; SetP $e 'Использование' $true }
function Filter($schema) { ,(G (G (G $schema 'НастройкиПоУмолчанию') 'Отбор') 'Элементы') }
$script:fails = 0
function Check([string]$name, [scriptblock]$cond) {
  try { if (& $cond) { "PASS $name" } else { $script:fails++; "FAIL ${name}: condition false" } }
  catch { $script:fails++; "FAIL ${name}: " + (Err $_) } }
function Done { if ($script:fails -eq 0) { 'ALL PASS' } else { "FAILED: $($script:fails)" } }
```

**Interfaces:**
- Produces (усе `Экспорт`, область `ПрограммныйИнтерфейс`):
  - `ТекстНабораДанных(ПолноеИмяДокумента) → Строка` — шаблон з Global Constraints.
  - `СхемаОтбораДокумента(ПолноеИмяДокумента) → СхемаКомпоновкиДанных` — як нинішня
    `ПолучитьСКД` (джерело `ИсточникДанных1`/`local`, набір-запит з ім'ям = повне ім'я,
    `АвтоЗаполнениеДоступныхПолей`, вибране поле `Ссылка`, групування з автополями й
    автопорядком, параметр `ПараметрСсылка` типу `ДокументСсылка.<Имя>`,
    `ВключатьВДоступныеПоля`, `ЗапрещатьНезаполненныеЗначения`, `Использование = Всегда`), але
    текст — `ТекстНабораДанных`.
  - `ОбновитьТекстНабора(СхемаКД, ПолноеИмяДокумента)` — `НаборыДанных[0].Запрос =
    ТекстНабораДанных(...)`.
  - `СкомпилироватьПравило(ПолноеИмяДокумента, СхемаКД) → Структура` з ключами
    `ТекстЗапроса` (Строка), `ПараметрыЗапроса` (Структура «ім'я → значення», без
